Prueba de despliegue de SiGeRU en el servidor real - sigeru-srv (VirtualBox, Ubuntu Server 26.04.1 LTS)
Fecha: 2026-09-13
Ejecutado por SSH desde la PC anfitriona (cosmos2026@127.0.0.1 -p 2222)

Resumen de lo hecho:
- apt update && apt upgrade -y
- apt install apache2 php libapache2-mod-php php-mysql php-curl mysql-server mysql-client git
- a2enmod rewrite
- Repo copiado a /var/www/sigeru (via tar por SSH, no git clone: el repo de GitHub es
  privado y la VM no tiene credenciales cargadas; se decide no darselas por SSH no
  interactivo). chown www-data:www-data.
- MySQL: base "sigeru", usuario "sigeru"@"127.0.0.1" con contrasena generada
  (openssl rand), GRANT ALL PRIVILEGES. La contrasena real vive fuera del repo,
  en vm-ubuntu/ssh/sigeru-db-password.txt (mismo criterio que backup.conf real y
  el user-data real del autoinstall).
- Importados database/schema.sql y database/datos_prueba.sql (15 tablas).
- Apache: administracion-sistemas-operativos/config/... no, en este caso el conf vivo
  es /etc/apache2/conf-available/sigeru.conf con Alias /sigeru + <Directory> AllowOverride
  All + Require all granted + SetEnv SIGERU_DB_* (host/port/name/user/pass) para que
  config/database.php de las APIs encuentre las credenciales reales sin tocar el codigo.

Nota tecnica sobre la etapa de Limpieza: tests/correr-tests.php se corre por PHP CLI, y esa
etapa conecta directo a la base (sin pasar por Apache), por lo que necesita las mismas
variables SIGERU_DB_* exportadas en el shell antes de invocar php; si se corre sin
exportarlas, cae a los valores por defecto (root sin contrasena) que en Ubuntu no
funcionan por TCP (root usa auth_socket). No es un bug del proyecto, es la diferencia
entre correr los tests via Apache (que ya tiene las variables por SetEnv) y por CLI.
