Prueba de los scripts de respaldo y administracion en el servidor real - sigeru-srv
Fecha: 2026-09-13
(La primera prueba de estos scripts fue en un contenedor Ubuntu, 12/09/2026,
ver 2026-09-12-prueba-respaldo.txt y 2026-09-12-prueba-admin.txt. Esta es la segunda,
contra el servidor real.)

$ cd /var/www/sigeru/administracion-sistemas-operativos/scripts/respaldo
$ sudo ./instalar.sh
== Instalando las rutinas de respaldo de SiGeRU en /opt/sigeru ==
   backup.sh, restaurar.sh y backup.conf en /opt/sigeru/respaldo/
   sigeru-admin.sh y sus modulos en /opt/sigeru/admin/ (comando: sigeru-admin)
   carpeta de respaldos: /backups (solo root)
   log: /var/log/sigeru-backup.log
   tarea diaria (03:00) en /etc/cron.d/sigeru-backup
   cron esta corriendo.

Se edito /opt/sigeru/respaldo/backup.conf con las credenciales reales (DB_USUARIO=sigeru,
DB_CLAVE=<la generada para el usuario de MySQL>, ver 2026-09-13-prueba-despliegue-servidor-real.txt).
Este archivo no se commitea (vive solo en el servidor, permisos 640 root).

=== Correccion: ssh no arrancaba solo ===
El primer chequeo de servicios mostro "ssh ... disabled": el servicio corre ahora
mismo pero no estaba habilitado para el proximo arranque. Sin esto, despues de un
reinicio la unica forma de entrar hubiera sido la consola grafica de VirtualBox.

$ sudo systemctl enable ssh
Created symlink /etc/systemd/system/sshd.service -> /usr/lib/systemd/system/ssh.service.
Created symlink /etc/systemd/system/multi-user.target.wants/ssh.service -> /usr/lib/systemd/system/ssh.service.

$ sudo sigeru-admin servicios estado

apache2    active       enabled
mysql      active       enabled
ssh        active       enabled
cron       active       enabled
